# SiYuan Connector for WorkBuddy

The official connector that lets [WorkBuddy](https://www.workbuddy.cn) read and write a
[SiYuan](https://b3log.org/siyuan/) workspace over the Model Context Protocol.

[中文说明](README.zh-CN.md)

| | |
|---|---|
| Package name | `siyuan` |
| Display name | SiYuan Official Connector / 思源笔记官方连接器 |
| Transport | MCP Streamable HTTP, `POST {base}/mcp` |
| Auth | SiYuan API token, sent as `Authorization: Token <token>` |
| Current version | 1.0.3 |
| Minimum SiYuan | 3.7.0 (the release that introduced the built-in MCP service) |
| Minimum WorkBuddy | 4.23.0 |
| License | AGPL-3.0 |

## What it can do

The connector proxies SiYuan's built-in MCP tools, so the agent works with the real
workspace instead of a copy:

- **Search** — full-text, semantic and attachment search, plus SQL-style filtering.
- **Read** — documents, blocks, kramdown source, outlines, backlinks, attributes, history.
- **Write** — create, rename, move, duplicate and delete documents; insert, update and delete blocks.
- **Organize** — notebooks, tags, bookmarks, daily notes, attribute views (databases), templates.
- **Move data** — export to Markdown, HTML or DOCX, import files, manage assets and images.

Write operations touch real notes. Locked notebooks, read-only workspaces and the
per-workspace MCP capability settings still apply, exactly as they do in SiYuan.

## Install

1. Open the connector marketplace in WorkBuddy and search for **思源笔记 / SiYuan**.
2. Install **思源笔记官方连接器**, then fill in the four fields described below.
3. Chat with the agent; a first request such as "search my SiYuan notes for project plans"
   confirms the connection.

The API token lives in SiYuan under **Settings → Authentication → API token**. It grants
administrator access to the workspace, so treat it like a password.

## Configuration

| Field | Meaning | Default | Notes |
|---|---|---|---|
| `SCHEMA` | Protocol | `http` | `http` or `https` only, without `://`. Use `http` for a local kernel. |
| `SIYUAN_HOST` | Host name or IP | `127.0.0.1` | **No scheme, no port, no path.** |
| `SIYUAN_PORT` | Port | `6806` | Digits only. Public HTTPS deployments usually use `443`. |
| `SIYUAN_API_TOKEN` | API token | — | From **Settings → Authentication → API token**. |

Common combinations:

| Scenario | `SCHEMA` | `SIYUAN_HOST` | `SIYUAN_PORT` |
|---|---|---|---|
| SiYuan on the same machine | `http` | `127.0.0.1` | `6806` |
| SiYuan on the LAN | `http` | `192.168.1.8` | `6806` |
| Behind a reverse proxy | `https` | `siyuan.example.com` | `443` |

> `SIYUAN_HOST` used to accept `host:port` as a single value. That is rejected by the
> client-side hostname check and produced the `Invalid hostname variable SIYUAN_HOST`
> error fixed in 1.0.3 — the port now has its own field. See [CHANGELOG.md](CHANGELOG.md).

Credentials are stored encrypted in the local WorkBuddy profile (`~/.workbuddy`) and are
never sent anywhere except the SiYuan endpoint you configure.

## Repository layout

```
.
├── connector-meta.json          # marketplace metadata: names, descriptions, examples, version
├── mcp.json                     # MCP server declaration with ${VAR} URL template
├── token-schema.json            # connection form: SCHEMA / SIYUAN_HOST / SIYUAN_PORT / SIYUAN_API_TOKEN
├── icon.svg                     # listing icon
├── skills/siyuan/SKILL.md       # agent skill: tool overview and usage rules
├── scripts/build.py             # validation + packaging into dist/
├── scripts/smoke_test.py        # dependency-free MCP handshake check
└── .github/workflows/           # validate on push, build the zip on tag
```

`.codebuddy-plugin/plugin.json` and `ai.workbuddy/token-schema.json` are **generated by the
WorkBuddy platform** from the files above when a version is published. They are not part
of this repository; editing them by hand has no effect.

## Build

Python 3.9+ with the standard library is all you need.

```bash
python3 scripts/build.py --check   # validate only
python3 scripts/build.py           # validate + write dist/siyuan-connector-<version>.zip
```

The archive is flat on purpose: `connector-meta.json` sits at the archive root, because
the platform rejects packages wrapped in an extra directory. Entry timestamps are fixed,
so the same sources always produce the same sha256.

## Smoke test

`scripts/smoke_test.py` performs the same handshake WorkBuddy performs — `initialize` →
`notifications/initialized` → `tools/list` — without any third-party dependency. Run it
before opening an issue about connectivity:

```bash
SIYUAN_API_TOKEN=xxxx python3 scripts/smoke_test.py
python3 scripts/smoke_test.py --url https://siyuan.example.com --token xxxx
python3 scripts/smoke_test.py --url https://siyuan.example.com --token xxxx --insecure
```

```
endpoint https://siyuan.example.com/mcp
server   SiYuan 3.8.11 (MCP 2025-11-25)
session  KC4X5EISEFOWVS3UIPQWSRV7JB
tools    31 available
         asset, attr, bazaar, block, bookmark, dailynote, database, document, ...
OK
```

`401` means the token is wrong or was regenerated, `403` means it is not an administrator
token, and `tools 0 available` points at the workspace MCP capability settings.

## Release a new version

1. Bump `version` in `connector-meta.json` and add a [CHANGELOG.md](CHANGELOG.md) entry.
2. Commit, then tag and push:

   ```bash
   git tag v1.0.4
   git push origin v1.0.4
   ```

3. The `Release` workflow checks that the tag matches `connector-meta.json`, builds the
   zip and attaches it to the GitHub release.
4. In the WorkBuddy open platform, use **更新版本** on the existing listing (never create a
   second listing), upload `dist/siyuan-connector-<version>.zip`, submit for review, then
   publish once approval completes.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `MCP server "connector:siyuan" is not registered` | The package failed to parse, so the server was never registered (wrong manifest, a directory-wrapped zip, or a field the client rejects) | Confirm the version in the marketplace, reinstall, and run `scripts/build.py --check` on the sources |
| `Invalid hostname variable SIYUAN_HOST` | `SIYUAN_HOST` contains a port or scheme | Move the port to `SIYUAN_PORT`, drop `http://` — fixed in 1.0.3 |
| `401 Unauthorized` | Token was regenerated or copied with whitespace | Re-copy from **Settings → Authentication → API token** |
| `403 Forbidden` | Token is not an administrator token, or the workspace is read-only for this client | Use the workspace administrator token; unlock the workspace |
| Connection refused / timeout | Kernel not running, or listening on loopback while WorkBuddy runs elsewhere | Start SiYuan, or point the connector at the machine that runs the kernel |
| TLS error for a self-signed certificate | Certificate not trusted by the client | Use a trusted certificate, or verify first with `scripts/smoke_test.py --insecure` |

## Security

- The API token is workspace-administrator level: it can read, write and delete any note.
- Only point the connector at a SiYuan instance you control, and prefer `https` for anything
  that leaves localhost.
- Rotate the token in SiYuan if it may have leaked; the connector picks up the new value
  after you update the field.
- Report security issues privately to the maintainers instead of opening a public issue.
